# 图片 OBS 适配（2026-11-09）

## 保存策略

画布上传、图片创作参考图、AI 生成原图及视频输入适配副本均使用 `get_storage()`。
以下四项配置完整时，新文件写入 OBS，否则写入 `STORAGE_ROOT`：

- `HUAWEI_CLOUD_OBS_ENDPOINT`
- `HUAWEI_CLOUD_OBS_BUCKET`
- `HUAWEI_CLOUD_OBS_ACCESS_KEY`
- `HUAWEI_CLOUD_OBS_SECRET_KEY`

每条新素材记录标记真实的 `storage_provider`。OBS 写入失败会报告失败，不会静默转存本地。
已有本地素材继续按 `local` 标记读取，不会因启用 OBS 自动迁移或删除。
本地预览启动器当前将 OBS bucket 留空，实际本地预览仍使用磁盘；本次没有更改云端配置或搬迁历史文件。

## 调用与读取

- 展示：稳定素材接口按素材存储标记返回本地文件或 OBS 预签名链接；允许展示缩略图。
- 下载：OBS 链接使用 attachment 响应头，禁止缩略图处理，下载原始字节。
- 生图/改图、文字建议、画布协作、视频 AI 审理：服务端通过存储驱动读取原图，校验大小、格式及指纹，将真实图片作为视觉输入；不抓取浏览器缩略图地址。
- 视频生成前检查：本地和 OBS 使用同一字节读取接口，检查格式、尺寸、比例、大小和审理时的素材快照。
- 普通上传图需要适配时，副本也写入当前存储。原图保留。
- 平台生成图片保留原始字节及内嵌信息，不自动缩放或转码；不符合视频输入约束时阻止提交并提示。
- 视频厂商取图：继续使用站点签名素材接口。OBS 素材重定向到原始对象的签名 GET 地址，不附加图片处理参数。
- 取消或过期审理：等待进行中的副本上传结束后清理未提交的副本；写入失败的副本不会登记为 ready。
- 素材库封面与历史素材按各自存储标记读取。

## 验证范围

`tests/test_image_obs.py` 的 13 项测试通过内存 OBS SDK 模拟，执行真实的服务、存储驱动和 HTTP 路由代码。
涵盖上传、生成、继续修改、视觉输入、视频审理/提交、原图保留、下载头、混合存储、篡改拒绝、保存重试、失败与取消清理。
相关资产、生图、看图、审理和素材库回归测试也已通过。测试不使用真实模型或 OBS 凭据。

尚未验证真实 OBS 桶的读写权限、网络可达性、图像处理能力及视频厂商是否成功跟随签名接口的 302。
正式部署仍需可供厂商访问的公网 `APP_BASE_URL`；仅把图片存入 OBS 不会使 localhost 的厂商入口变为公网地址。
本次不涉及 GitHub 合并、推送或生产部署。
