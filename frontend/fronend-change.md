### 一、 从对话开始到现在前端究竟改了什么？

最初的前端版本是一个**传统的“左右分栏式”界面**（左侧聊天框，右侧参数面板）。为了提供更直观、更自由的工作流交互，我们将其重构成了**节点流无限画布 + 悬浮 Agent 抽屉**架构：

1. **界面交互形态从“表单对话”演进为“可视化节点工作流（Node Flow）”**：
* 原本的左右双栏布局被替换为一个支持无限平移（`pan`）与缩放（`zoom`）的点阵网格画布。
* 创作要素（文本脚本、参考图、视频生成结果）被抽离封装为**卡片节点（FlowNode）**，节点之间通过 SVG 贝塞尔曲线连接表示上下文流动关系。


2. **多节点框选与协同移动**：
* 实现了类似桌面的鼠标拖拽矩形选框多选能力（包含碰撞检测计算）。
* 选中多个节点后，按住任意一个节点拖动可带动所有选中节点同步平移。


3. **Agent 交互转为独立抽屉（Flyout Drawer）与多节点参考绑定**：
* 将原来的左侧对话区做成了右侧可滑动展开/收起的 Agent 抽屉。
* 支持通过多选或直接将节点**拖入 Agent 面板**作为创作参考依据（`referencedNodes`），顶部动态展示参考节点胶囊标签。
* 将收起逻辑优化为**在画布空白网格双击（dblclick）才收起**，防止用户在画布单选、多选或框选时意外关闭面板。


4. **对话项目隔离与本地缓存机制**：
* 添加了前端项目持久化缓存兜底（`localStorage`），使得切换不同对话时能记住各自节点的位置、连线及编辑状态。

### 二、 为什么必须改动后端？（核心痛点）

在原来的后端架构下，后端只记录了单条对话记录以及单一维度的视频生成方案（`current_spec`）。
这导致了一个致命问题：**节点在画布上的坐标（x, y）、连线关系（connections）、新增/删除的临时节点等状态，后端根本没有地方保存！**
如果没有后端支持，用户换台电脑、清除浏览器缓存，或者多端协作时，画布上的所有节点和连线就会全部丢失或回退到最初写死的两个默认卡片。

---

### 三、 方便发给后端的改动需求说明（可直接复制）

> **【前端工作流画布重构 - 后端数据同步需求】**
> 前端已从原本的“聊天列表+表单”升级为了**“节点式画布工作台（无限画布/节点/连线）”**。为保证每个创作对话（Conversation）下的画布节点、连线关系及排版位置能够真实持久化，需要后端配合支持以下改动：

#### 1. 数据模型改动（建议方案）

在 `projects` 表（或 `conversations` 表）中新增一个 JSON 类型的字段：**`canvas_data`**（允许为 `null`）。

**`canvas_data` 结构格式示例：**

```json
{
  "pan": { "x": 120, "y": 120 },
  "zoom": 1.0,
  "nodes": [
    {
      "id": "node_text_1",
      "type": "text",
      "title": "分镜脚本",
      "x": 160,
      "y": 160,
      "content": "镜头脚本内容描述..."
    },
    {
      "id": "node_img_1",
      "type": "image",
      "title": "参考图",
      "x": 540,
      "y": 160,
      "url": "https://..."
    },
    {
      "id": "node_video_1",
      "type": "video",
      "title": "生成视频结果",
      "x": 920,
      "y": 160,
      "url": "/api/v1/assets/xxx/content"
    }
  ],
  "connections": [
    {
      "id": "c_1",
      "from": "node_text_1",
      "to": "node_img_1"
    },
    {
      "id": "c_2",
      "from": "node_img_1",
      "to": "node_video_1"
    }
  ]
}

```

#### 2. 接口调整需求

1. **获取项目方案详情接口：`GET /conversations/{conversation_id}/project**`
* 返回的 `project` 对象中需包含该字段：`canvas_data: {...}`。
* 若该对话为刚创建的新项目且 `canvas_data` 为空，可返回 `null`，由前端执行默认初始化。


2. **新增/更新画布数据保存接口**（二选一）：
* **方式 A（独立轻量接口，推荐）**：
* 请求：`PUT /conversations/{conversation_id}/canvas`
* Body：传入上述 `canvas_data` 的完整 JSON。
* 说明：前端在节点拖拽放下、连线完成、删除节点时自动静默调用此接口做持久化。


* **方式 B（并入方案保存接口）**：
* 在现有的 `PUT /conversations/{conversation_id}/project` 中接收 `canvas_data` 字段并落库。




3. **视频生成完成后的异步回调（Task Callback）**：
* 当底模视频渲染任务状态变为 `succeeded` 时，后端在将结果 asset 绑定的同时，如果能顺便在 `canvas_data.nodes` 数组里追加该视频节点并连线，多端刷新后也能直接看到结果节点。
